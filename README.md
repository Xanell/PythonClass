# 🚗 Автомойка самообслуживания (учебный проект)

## Описание проекта

Данный проект реализует упрощённую модель вендингового автомата на примере автомойки самообслуживания. Разработан в рамках изучения принципов объектно-ориентированного программирования (ООП) на языке Python.

Система моделирует работу бокса ручной автомойки (`StandardWashBox`), который поддерживает различные режимы мойки, способы оплаты (наличные или мобильное приложение), контроль запасов химии (пены и воска), учёт выручки и ведение истории операций.

Проект демонстрирует:
- наследование (базовый абстрактный класс `AbstractCarWash`);
- полиморфизм (абстрактные методы, переопределённые в наследнике);
- использование перечислений для статусов и режимов;
- обработку исключений и валидацию входных данных;
- ведение журналов оплат и ошибок.

## Архитектура

### Основные классы

| Класс               | Описание                                                                                     |
|---------------------|----------------------------------------------------------------------------------------------|
| `AbstractCarWash`   | Абстрактный базовый класс автомойки. Определяет общую логику: статус бокса, кассу, выручку, историю платежей и ошибок, метод проведения оплаты. Содержит абстрактные методы `get_resources` и `get_error_history_log`, которые должны быть реализованы в дочерних классах. |
| `StandardWashBox`   | Конкретная реализация ручного бокса мойки. Наследуется от `AbstractCarWash`. Управляет запасами пены и воска, рассчитывает тарифы и расход ресурсов, запускает сессии мойки с разными типами оплаты. |
| `User`              | Пользователь системы с балансом для оплаты через приложение.                                |

### Перечисления (`Enums.py`)

| Enum           | Значения                                      | Описание                        |

| `BoxStatus`    | `FREE`, `BUSY`, `MAINTENANCE`                 | Статус бокса                    |
| `ResourceType` | `WATER`, `FOAM`, `WAX`, `OSMOS`, `SHAMPOO`    | Виды используемых ресурсов      |

## Функциональность

### 1. Базовые операции (унаследованы от `AbstractCarWash`)

- **Проверка статуса бокса** – `get_status_report()` возвращает номер бокса, сумму наличных в кассе и текущий статус.
- **Перевод в режим обслуживания** – `set_maintenance_status()` / `finish_maintenance_status()`.
- **Проведение оплаты** – `process_payment(amount, payment_type, user)`:
  - при оплате наличными увеличивает `cash_box`;
  - при оплате через приложение списывает средства с баланса пользователя;
  - всегда увеличивает `total_revenue`.
- **Ведение журнала оплат** – `add_pay_history_log(total_price, time_passed)` добавляет запись о завершённой сессии в `pay_history_log`; `get_pay_history_log()` возвращает этот журнал.
- **Ведение журнала ошибок** – `add_error_history_log(error)` добавляет сообщение об ошибке в `error_history_log`; `get_error_history_log()` возвращает журнал.
- **Сбор статистики** – `get_statistics()` возвращает сводку по боксу: номер, адрес, касса, общая выручка, количество моек, текущие ресурсы и список ошибок.

### 2. Управление ресурсами (для `StandardWashBox`)

- `restock_foam(foam_liters)` – пополнение бака пены.
- `restock_wax(wax_liters)` – пополнение бака воска.
- При попытке залить больше максимума выводится сообщение об аварийном сливе излишков и записывается ошибка в журнал.
- Пополнение автоматически переводит бокс в режим обслуживания (`MAINTENANCE`), после чего требуется вызвать `finish_maintenance_status()` для возврата в работу.

### 3. Запуск мойки

Универсальный метод `start_wash_session(mode, payment_type, user=None, duration_seconds=0, cash_amount=0.0)`:

- **Режим оплаты `APP`:**
  - Требуется указать пользователя и длительность (`duration_seconds > 0`).
  - Предварительно проверяется достаточность баланса: стоимость = длительность × тариф.
  - Мойка продолжается ровно указанное время, после чего списывается полная стоимость с баланса пользователя.

- **Режим оплаты `CASH`:**
  - Пользователь вносит наличную сумму `cash_amount`.
  - Мойка продолжается, пока внесённой суммы хватает на оплату каждой следующей секунды.
  - По окончании фиксируется фактическое время и стоимость, которые проводятся в кассу.

- **Остановка при нехватке ресурсов:**
  - Если во время работы заканчивается пена или воск, бокс переводится в состояние `MAINTENANCE`, а сессия завершается.
  - Оплата списывается только за фактически оказанное время.

- **Журналирование:**
  - Каждая завершённая сессия (успешная или аварийная) добавляется в журнал оплат через `add_pay_history_log`.
  - Любая ошибка (нехватка денег, ресурсов и т.д.) добавляется в журнал ошибок через `add_error_history_log`.
